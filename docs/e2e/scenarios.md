# E2Eテスト：テスト項目

| 項目 | 内容 |
|---|---|
| 対象 | ユーザー画面（管理画面は実装後に追加） |
| ブランチ | test/e2e |
| 根拠 | docs/03-page-list.md、docs/04-feature-list.md、docs/07-basic-design.md、docs/uat/ の各シナリオ |
| 画面幅 | 1回目：PC（1280×800）のみ。SP（414×896）はフロントエンドの実装後に追加する |
| 作成日 | 2026-10-29 |

UATは機能ごとの受け入れ、E2Eは利用者の流れ単位の回帰テスト。細かい入力チェック・境界値はPHPUnitとUATに任せ、ここでは「一連の流れが最後まで通るか」と「流れの中で次の画面に正しく引き継がれるか」を確かめる。

## 方針

- 実行のたびに専用DB（sf_db_e2e）を `migrate:fresh --seed` で作り直す。開発用DBは使わない。
- 会員はテストごとに会員登録画面から新しく作る（メールは `e2e-<時刻>-<連番>@example.com`）。Stripeの顧客残高の影響を受けないようにするため。
- メールは Mailpit の API で、宛先を指定して取得し、件名・本文を確かめる。
- 要素は `getByRole` / `getByLabel` / 表示テキストで取り、クラス名やHTMLの構造に頼らない（フロントエンドの実装で壊れにくくする）。
- クレジットカード（Stripe Checkout）を通る項目には `@stripe` タグを付け、普段の実行（`npm test`）から外す。必要なときに `npm run test:stripe` で流す。
- 代金引換・銀行振込は普段の実行に含める（銀行振込はサーバーから Stripe のテストAPIを呼ぶ）。

## テスト項目

| ID | 流れ | 手順 | 確かめること |
|---|---|---|---|
| E-1 | 会員登録 → ログアウト → ログイン | 商品一覧 → ヘッダーの「ログイン」→「会員登録」→ 入力して登録 → ログアウト → ログインページでログイン | 登録後に、会員登録の前に見ていたページ（商品一覧）へ戻る。ヘッダーが「マイページ」「ログアウト」に変わる。ログアウト後は「ログイン」に戻る。ログイン後も元のページへ戻る |
| E-2 | ログインの失敗 | 誤ったパスワードでログイン | ログインページに留まり、エラーメッセージが出る。ログイン状態にならない |
| E-3 | 商品を探してカートに入れる | ログイン済みで、トップ →「オンラインショップ」→ 商品詳細 →「カートに入れる」→ カートのモーダル →「カートを見る」→ カートページ | トップのおすすめ商品・お知らせが表示される。カートページに商品名・数量・金額・合計が出る。数量の変更で合計が変わる。削除で商品が消える |
| E-4 | カートから購入（代金引換・住所追加） | 2商品をカートに入れる →「購入する」→ 住所追加モーダルで住所を追加 → 支払方法「代金引換」→ 注文を確定 | 購入ページの初期値が会員の氏名・電話・住所。追加した住所が選択された状態になり、送料が変わる。「代引手数料 330円」が合計に加わる。サンクスページへ進み、カートが空になる。サンクスメール（宛先・件名・商品・代引手数料・合計）が届く。マイページの購入履歴の「詳細」に同じ内容が出る |
| E-5 | 商品詳細から購入（銀行振込・戻る） | 商品詳細の「購入する」→ 数量を変えて支払方法「銀行振込」→ 注文を確定 → 振込先のご案内で「戻る」→ もう一度確定 →「振込み」 | 振込先（銀行名・支店名・口座種別・口座番号・口座名義・振込金額）が表示される。「戻る」で購入ページに戻り、入力内容が残る。「振込み」でサンクスページへ。カートは変わらない。メールとマイページの「詳細」に振込先が出る |
| E-6 | 予約（銀行振込） | 予約限定商品の詳細 →「予約する」→ 数量・支払方法「銀行振込」→ 予約を確定 → 振込先のご案内 →「振込み」 | 予約ページの支払方法がクレジットカードと銀行振込だけ。振込先のご案内を経て予約サンクスページへ。予約のサンクスメールが届く。マイページの予約履歴に出る |
| E-7 | 未ログインで購入を始める | 未ログインで商品詳細 → 会員登録の案内の「会員登録」→ 登録 →「購入する」 | 未ログインでは「購入する」の代わりに会員登録の案内が出る。登録後に商品詳細へ戻り、「購入する」から購入ページへ進める（お届け先氏名が登録した氏名） |
| E-8 | 登録情報の変更 | マイページ →「登録情報変更」→ 何も変えずに保存 → 氏名・住所を変えて保存 | 変更なしのときは「変更された項目はありません」と出て留まる。変更するとマイページへ戻り、新しい値が表示される。その後の購入ページの初期値にも反映される |
| E-9 | パスワード再設定 | ログイン →「パスワードをお忘れの方」→ メールアドレスを送信 → Mailpit のメールのリンクを開く → 新しいパスワードを設定 → ログイン → 同じリンクをもう一度開く | 送信後の案内文が出る。メールが届く。再設定後にログインページで完了の案内が出る。新しいパスワードでログインでき、古いパスワードではできない。使用済みのリンクは無効の案内になる |
| E-10 | 退会 | マイページ →「退会」→ 確認モーダルで退会 → 同じメールアドレスでログイン | 退会後はログアウト状態になる。同じメールアドレス・パスワードではログインできない |
| E-11 | お問い合わせ | トップ →「お問い合わせ」→ 未入力で送信 → 入力して送信 | 未入力ではエラーが出て留まる。入力して送信するとサンクスページへ。トップへのリンクで戻れる |
| E-12 | フッターの静的ページ | フッターのリンク（プライバシーポリシー・特定商取引法に基づく表記・利用規約・送料案内）を順に開く | 各ページが開き、見出しが出る |
| E-13 `@stripe` | カードで購入 | 購入ページで「クレジットカード」→ Stripe Checkout でテストカード（4242…）を入力して支払う | サイトのサンクスページに戻る。サンクスメールが届き、マイページの購入履歴に出る |
| E-14 `@stripe` | カードで予約 | 予約ページで「クレジットカード」→ Stripe Checkout で支払う | 予約サンクスページに戻る。予約のサンクスメールが届き、マイページの予約履歴に出る |

## 実行方法

リポジトリ直下で次を実行する。E2E用のアプリ（php-e2e・nginx-e2e、:8081）を起動し、CSS/JSをビルドし、専用DBを作り直してから Playwright のコンテナでテストを流す。

```bash
./e2e/run.sh                          # 普段の実行（@stripe 以外）
./e2e/run.sh stripe                   # クレジットカード（Stripe Checkout）の項目だけ
./e2e/run.sh tests/auth.spec.ts -g E-1   # 一部だけ（playwright test の引数をそのまま渡す）
```

- 前提：`src/.env.e2e`（`src/.env` をコピーし、`APP_ENV=e2e`・`APP_URL=http://nginx-e2e`・`DB_DATABASE=sf_db_e2e` に変える。gitignore 対象）と、MySQL の `sf_db_e2e`（sf_user に権限）。
- 結果のレポートは `e2e/playwright-report/`、失敗したテストのトレース・スクリーンショットは `e2e/test-results/` に出る。
