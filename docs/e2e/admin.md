# E2Eテスト：管理画面のテスト項目

共通の方針・実行方法は [scenarios.md](scenarios.md) を見る。ここに書くのは管理画面に固有の方針と項目。テストコードは `e2e/tests/admin/*.spec.ts`。

## 管理画面に固有の方針

- 管理者はシーダーの管理者（admin@admin.com）でログインする。会員のように毎回作ることはしない。
- 二段階認証（メールのコード）はE2E用アプリでもオンのままにし、コードは Mailpit のメールから読む。
- 管理者のログインには回数制限（メールアドレスとIPごとに1分5回で、成功も数える。コードの送信は1分10回）があるため、ログインそのものを確かめる項目（AE-1〜AE-3）以外は、PC・SP それぞれで最初に1回だけログインした状態（Playwright の storageState。`e2e/.auth/`、gitignore 対象）を使い回す。アプリ側の回数制限は変えない。
  - 構成（`playwright.config.ts`）：`pc-admin-auth`・`sp-admin-auth`（AE-1〜AE-3。ログイン済みの状態を使わない）→ `pc-admin-setup`・`sp-admin-setup`（最初に1回ログインして状態を保存する。失敗すると管理画面の項目は「実行されなかった」扱いになり、原因がここに出る）→ `pc-admin`・`sp-admin`（AE-4〜AE-11。保存した状態を使う）。
  - AE-3 で管理者のパスワードが変わると、変わる前に保存したログイン済みの状態はすべて無効になる（パスワードの変更で他の端末のセッションを切る仕様）。そのため `*-admin-auth` を `*-admin-setup` より前に流す（依存関係ではなく、プロジェクトの定義順で並べる。`*-admin-auth` の失敗で全体が止まらないようにするため）。
  - ログインの回数制限に当たったときは、画面に出る秒数だけ待って押し直す（`support/admin.ts` の `submitAdminLogin`）。AE-1〜AE-3 だけで5回使うため、PC → SP が続くと1分以内に5回を超えうる。
- AE-3（パスワード再設定）は管理者のパスワードを変えるため、最後にシーダーのパスワードに戻す。途中で失敗しても戻るよう、`finally` で別のコンテキストから再設定をやり直す。
- 一覧の検索で1件に絞れるよう、公開側で作る会員の氏名には時刻（と連番）を入れる。商品名・お知らせのタイトル・資材名・お問い合わせの姓にも時刻を入れる（PC と SP は同じDBを続けて使うため）。
- 公開側と管理画面にまたがる流れでは、公開側の操作はユーザー画面と同じく、テストごとに会員を新しく作って行う（共通の手順を使う）。
- 管理画面も PC と SP の両方で流す。`@stripe` の項目は置かない（取消などは銀行振込・代金引換の注文で確かめる）。
- エクスポートは、ダウンロードが始まりファイル名が正しいことまでを確かめる（列や中身は PHPUnit と UAT で確認済み）。
- 一覧の検索・ページ送り・入力チェックの細部は PHPUnit と UAT に任せ、ここでは流れの中で必要な検索（注文者名など）だけを使う。

## テスト項目

| ID | 流れ | 手順 | 確かめること |
|---|---|---|---|
| AE-1 | ログイン（二段階認証）→ ログアウト | 未ログインで /admin を開く → ログインページでメールアドレス・パスワードを入力 → コード入力画面で Mailpit のメールのコードを入れる → 管理画面トップ → ログアウト | 未ログインでは /admin/login へ移る。コードのメールが届く。コードを入れると管理画面トップに「各種一覧」「作成・登録」のリンクが出る。ログアウトでログインページに戻り、その後 /admin を開いてもログインページへ移る |
| AE-2 | ログインの失敗 | 誤ったパスワードでログイン → 正しいパスワードでログインし、誤ったコードを入れる | 誤ったパスワードではログインページに留まり、エラーが出る。誤ったコードではコード入力画面に留まり、エラーが出て、管理画面には入れない |
| AE-3 | パスワード再設定 | ログインページの「パスワードをお忘れの方」→ メールアドレスを送信 → Mailpit のメールのリンクを開く → 新しいパスワードを設定 → 新しいパスワードでログイン（コードも入れる）→ 古いパスワードでログイン → 最後に元のパスワードへ戻す | メールが届く。再設定後に完了の案内が出る。新しいパスワードでログインでき、古いパスワードではできない |
| AE-4 | 注文の確認と発送済み | 会員が代金引換で注文 → 管理画面の注文一覧で注文者名を検索 →「詳細」→ 閉じて「発送済」にチェック → 再読み込み → もう一度「詳細」→ エクスポート | 詳細モーダルに注文管理番号・商品・代引手数料・合計・配送先が、公開側の注文と同じ内容で出る。発送済みは再読み込みしても残り、詳細に「取り消す」が出なくなる。エクスポートで `注文一覧_YYYYMMDD.xlsx` がダウンロードされる |
| AE-5 | 注文の取消（銀行振込） | 会員が銀行振込で注文 → 管理画面の注文一覧で検索 →「詳細」→「取り消す」→ 確認で「取り消す」→ 会員のマイページの購入履歴を開く | 確認モーダルに銀行振込の案内が出る。取り消すと一覧に「注文を取り消しました。」が出て、その注文が「取消済」になる。マイページの購入履歴の「詳細」に「取消済」が出て、振込先は出ない |
| AE-6 | 予約の確認と取消 | 会員が銀行振込で予約 → 管理画面の予約一覧で予約者名を検索 →「詳細」→ 閉じてエクスポート →「詳細」→「取り消す」→ 確認で「取り消す」→ 会員のマイページの予約履歴を開く | 詳細モーダルに予約の内容が公開側と同じで出る。エクスポートで `予約一覧_YYYYMMDD.xlsx` がダウンロードされる。取り消すと「予約を取り消しました。」が出て「取消済」になる。マイページの予約履歴の「詳細」に「取消済」が出る |
| AE-7 | お問い合わせへの対応と返信 | 公開側でお問い合わせを送る → 管理画面のお問い合わせ一覧 →「詳細」→「対応済」にチェック → 再読み込み →「返信」→ タイトル・本文を入れて送信 → 確認で送信 | 一覧の先頭に送ったお問い合わせが出て、詳細に内容が出る。対応済みは再読み込みしても残る。送信後はお問い合わせ一覧に戻り「メールを送信しました。」が出る。お問い合わせのメールアドレスに件名「【しおや農園】{タイトル}」のメールが届き、本文の下に元のお問い合わせが引用される |
| AE-8 | 会員へのメールと退会した会員の削除 | 会員を登録 → 管理画面の会員一覧で氏名を検索 →「メール送信」→ 送信 → 会員が退会 → 会員一覧で検索 →「詳細」→「削除する」→ 確認で「削除する」 | メールが会員のメールアドレスに届く（引用は付かない）。退会後は一覧の状態が「退会済」になり、詳細に退会日と「削除する」が出る。削除すると一覧から消える |
| AE-9 | お知らせの作成・修正・削除 | 管理画面トップの「お知らせ作成」→ 作成 → 公開サイトのトップを開く → 一覧の「修正」→ 修正 → トップを開く → 一覧の「削除」→ 確認で削除 → トップを開く | 作成後は一覧の先頭に出て、トップのお知らせ欄に作成日つきで出る。修正後はトップに修正した内容が出て、日付は作成日のまま。削除後はトップから消える |
| AE-10 | 掲載商品の登録・修正・削除 | 管理画面トップの「掲載商品登録」→ 画像を選んで通常の商品を登録 → 公開側の商品一覧・商品詳細 →「カートに入れる」→ 一覧の「修正」で金額を変える → 公開側の商品詳細 → 一覧の「削除」→ 確認で削除 → 公開側の商品一覧 | 登録後は一覧に「商品を登録しました。」と商品が出る。公開側の商品一覧・詳細に出て、カートに入れられる。修正後は公開側に新しい金額が出る。削除後は公開側の商品一覧から消える |
| AE-11 | 資材の追加・修正・削除 | 管理画面の資材一覧 →「資材を追加」→ 追加 →「修正」で在庫数を基準値より少なくする →「削除」→ 確認で削除 | 追加後は表の最後に出る。在庫数を基準値より少なくすると「残りわずか」が出る。削除すると表から消える |

エクスポートは取り消す前に行う（取り消した予約は、発送状況を「取消済」にして検索しないとエクスポートに入らず、取り消した直後の一覧ではボタンが押せないため。2026-11-13、実装に合わせて手順の順を入れ替えた）。
