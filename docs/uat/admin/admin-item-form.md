# UAT：管理画面の掲載商品登録・修正

| 根拠 | docs/03-page-list.md「管理画面掲載商品登録ページ」「管理画面掲載商品修正ページ」、docs/05-table-specification.md（items）、docs/07-basic-design.md、Figma 掲載商品登録（174:56）・掲載商品修正（180:21）・item-update-button（182:28）、docs/uat/admin/admin-item.md・admin-mail.md のユーザー決定 |

これまでの管理画面から引き継ぐ事項：

- レイアウト（サイドメニュー、中央のページタイトル）、カードの形（幅800px・角丸30・影。メール作成と同じ）、入力欄の枠・プレースホルダーの色（#acacac）、Cache-Control: no-store、419（ページの有効期限切れ）のときは作成ページに戻して入力を残す（メール作成と同じ）。

登録・修正で決める事項（2026-11-09 ユーザー決定）：

- 項目名は一覧・詳細モーダルに合わせて「商品名・商品重量・商品金額・商品画像・商品紹介文・おすすめ商品・予約限定・予約可能数」にする（Figmaの登録ページの「商品価格」「商品詳細」は使わない）。重さは「2kg・5kg・10kg」と書く（Figmaの「㎏」は使わない）。
- 登録ページ：タイトルは #8f5e1c（メニューの「作成・登録」の下線と同じ色。Figmaの橙 #f0a13a は文字だと読みにくいため）。「登録する」ボタンは橙 #f0a13a の地に ink（#2e2e2e）の文字、ホバー・フォーカスは #c0822f＋影（公開側の「塗りボタンの文字は ink」に合わせる）。
- 修正ページ：タイトルと「修正する」ボタンは青 #2857ff（ボタンは白文字）。ボタンのホバー・フォーカスは #012ccb＋影（Figma 182:28）。
- 画面の形はFigmaどおり：商品名400px、金額200px＋「円(税込)」、画像の枠300×100（「ここに画像をドラッグ＆ドロップ または」と「画像を選択」）＋右にプレビュー170×100（画像がないときは灰色の地に「未設定」）、紹介文584×100、ラジオボタン、ボタンは幅400pxでカードの中央。
- 登録ページのラジオボタン（商品重量・おすすめ商品・予約限定）は、最初はすべて未選択にする（Figmaの登録ページは2kgが選ばれているが、選び直し忘れで違う重さが登録されるのを防ぐため。選び忘れはエラーで気づける）。
- SP：カードを画面幅に収め、入力欄とボタンは全幅。プレビューは画像の枠の下に置く。
- 商品画像：jpeg・png・webp で 10MB 以下（2026-11-10 に 2MB から変更。サーバーで長辺1200px以下の webp に縮小して image/product/uploads/ に保存する）。選んだ・落とした時点で、ブラウザでも形式と大きさを確かめ、合わなければ選択を取り消して「jpeg・png・webp の10MB以下の画像を選んでください」を画像の欄の下に出す。サーバー側でも形式（中身で判定）と大きさを確かめ、10MBを超えると「商品画像は10MB以下にしてください」。形式は正しいが中身が壊れていて GD で読み込めない画像は「画像を読み込めませんでした。別の画像を選んでください」、縦横が 8000×8000（64,000,000画素）を超える画像は「画像の縦横が大きすぎます。小さい画像を選んでください」（GD のメモリ不足を防ぐため。2026-11-10 ユーザー了承）。jpeg は EXIF の向きを補正してから保存する（exif 拡張。2026-11-10 ユーザー了承）。登録では必須。修正では任意で、選ばなければ今の画像のまま。選んだ時点（ドラッグ＆ドロップでも）でプレビューに表示する。修正で画像を差し替えて更新が確定したあとに、古い画像が image/product/uploads/ の中のファイルなら消す（2026-11-10 ユーザー決定。アップロードした画像はハッシュ名で商品ごとに別のファイル。シードの画像（image/product/ 直下など uploads の外）は消さない。更新が失敗したとき・画像を選ばなかったときも消さない）。
- 商品名は必須・255文字以内。商品金額は必須・1〜100,000の整数。商品紹介文は必須・1,000文字以内。
- 同じ商品名と同じ重さの組み合わせが、削除していない商品にすでにあれば登録・修正できない（修正では自分自身は除く）。削除した商品と同じ組み合わせは登録できる。重複の判定は DB の照合順序 utf8mb4_unicode_ci で行うため、ひらがなとカタカナ・濁点の有無・大文字小文字・全角半角は同じとみなす（「じゃがいも」と「ジャガイモ」は重複になる。2026-11-10 ユーザー決定。意図どおり）。
- 予約可能数：「予約限定」で「限定」を選んだときは「上限なし」「上限あり」のラジオを選び、「上限あり」のときだけ数（1〜999の整数）を入力できる。「通常」のときは予約可能数の全体が無効（グレー）になり「通常の商品は予約を受け付けません」と添え、保存する値は空（上限なし扱いではなく、予約自体がない）。
- 予約可能数の上限の数は 1〜999 の整数（1,000以上はエラー。メッセージは「予約可能数は999以下で入力してください」）。
- 登録ページにも、修正ページと同じ位置・見た目で「一覧へ戻る」のリンクを置く。
- ラジオボタンの未選択の文字色は #6b6b6b（Figmaの #acacac は読みにくいため濃くした。丸の枠は #dddddd のまま）。
- 画像が未設定のときのプレビューは、#e6e6e6 の地に #6b6b6b の「未設定」（Figmaの #c4c4c4 に白文字は読みにくいため）。
- 上限を下げる修正と同時に予約が確定すると、予約数が上限を少し超えることがある。予約作成時と同じく許容する（docs/uat/user/reservation.md の決定）。
- 商品金額・予約可能数の数は、全角数字を半角にし、前後の空白を除いてから検証する。
- トップのおすすめ商品は、おすすめ「はい」の商品からランダムに最大3件を表示する（ID順ではない）。
- 修正で、上限をすでに予約された数より小さくすることはできない（「すでに150個の予約があるため、150以上にしてください」）。
- 通常と限定は修正で自由に切り替えられる。限定に変えた商品は、カートに入っていても公開側の既存の仕組みで取り除かれる。通常に変えても、これまでの予約の記録は残る。
- 登録・修正のあとは掲載商品一覧に戻り、表の上に緑の文字で「商品を登録しました。」「商品を修正しました。」と表示する。
- 修正ページは /admin/items/edit/{商品ID}。更新は POST /admin/items/update で、商品IDは hidden で送る。削除済み・存在しない商品の修正ページを開いたとき、更新したときは、一覧に戻して赤字で「商品が見つかりません。」と表示する。
- 一覧の「修正」のリンクとメニューの「掲載商品登録」のリンクは、ルート名で作る。修正ページではメニューの「掲載商品一覧」を太字にする。
- 修正しても、過去の注文・予約の商品名・重さ・金額は変わらない（注文した時点の値を保存しているため）。画像は今の商品の画像を表示するため、差し替えるとマイページの履歴の画像も変わる（了承済み）。

## 受け入れ条件

| ID | 条件 |
|---|---|
| AC-1 | 未ログイン・会員としてのログインでは登録・修正ページを開けず、/admin/login へ移動する。登録・更新のリクエストも受け付けない |
| AC-2 | 管理者としてログインすると、サイドメニューとトップページの「掲載商品登録」から登録ページを開ける。サイドメニュー、中央のタイトル「掲載商品登録」（#8f5e1c）、入力のカードが表示される |
| AC-3 | 登録ページの項目は、商品名・商品重量（2kg / 5kg / 10kg）・商品金額（「円(税込)」）・商品画像（ドラッグ＆ドロップの枠と「画像を選択」、プレビュー）・商品紹介文・おすすめ商品（はい / いいえ）・予約限定（限定 / 通常）・予約可能数（上限なし / 上限あり＋数「個」）と「登録する」ボタンで、入力欄にはFigmaの例（「例：じゃがいも」など）がプレースホルダーとして出る。ラジオボタンは最初はすべて未選択 |
| AC-4 | 「画像を選択」で画像を選ぶか、枠に画像をドラッグ＆ドロップすると、プレビューの「未設定」がその画像に変わる |

| AC-6 | 登録した商品は、通常の商品なら公開側の商品一覧・商品詳細に出てカートに入れられ、予約限定の商品なら予約ページから予約できる。「おすすめ商品：はい」の商品はトップのおすすめの候補になる |

| AC-8 | 同じ商品名と同じ重さの、削除していない商品がすでにあると、「{商品名} {重さ}kg はすでに登録されています」と表示され、登録されない。削除した商品と同じ組み合わせは登録できる |
| AC-9 | 「予約限定：通常」を選んでいるときは、予約可能数の全体が無効（グレー）になり「通常の商品は予約を受け付けません」が表示される。「限定」に切り替えると「上限なし / 上限あり」を選べるようになり、「上限あり」のときだけ数を入力できる |
| AC-10 | 「限定・上限なし」で登録した商品は、一覧の詳細モーダルで予約可能数が「上限なし」になる。「限定・上限あり 200」なら「200（残り200）」、「通常」なら「無」になる |
| AC-11 | 「限定・上限あり」で数が空・0以下・1,000以上・整数でないと、エラーになり登録されない |
| AC-12 | 一覧の「修正」を押すと /admin/items/edit/{商品ID} の修正ページが開き、中央のタイトル「掲載商品修正」（青）と、今の値が入った入力欄・選択済みのラジオ・今の画像のプレビューが表示される。サイドメニューは「掲載商品一覧」が太字になる |
| AC-13 | 値を変えて「修正する」を押すと、一覧に戻って「商品を修正しました。」が緑の文字で表示され、一覧・詳細モーダル・公開側の商品ページに新しい値が出る |
| AC-14 | 修正で画像を選ばなければ、今の画像のまま保存される。新しい画像を選ぶと差し替わる |
| AC-15 | 修正で入力に誤りがあると、更新されずに修正ページに戻り、エラーが表示され、入力した値が残る（AC-7・AC-8・AC-11 と同じ基準。重複の判定で自分自身は除く） |
| AC-16 | 修正で予約可能数の上限を、すでに予約された数より小さくすると「すでに◯個の予約があるため、◯以上にしてください」と表示され、更新されない。予約された数と同じ値にはできる |
| AC-17 | 修正で「限定」⇔「通常」を切り替えられる。限定に変えた商品はカートから取り除かれ、通常に変えた商品は公開側でカートに入れられるようになる |
| AC-18 | 削除済み・存在しない商品の修正ページを開くと、一覧に戻って赤字で「商品が見つかりません。」が表示される。修正ページを開いたあとに商品が削除されてから「修正する」を押しても、同じ表示になり何も変わらない |
| AC-19 | 修正しても、その商品の過去の注文・予約の商品名・重さ・金額（マイページ・注文一覧・予約一覧の詳細）は変わらない |
| AC-20 | 「登録する」「修正する」を押したあとは二重に送信されない（ボタンを連打しても1件だけ登録される） |
| AC-21 | ページの有効期限が切れて送信できなかったとき（419）は、エラーページではなく同じページに戻り、案内が表示され、画像以外の入力が残る |
| AC-22 | 登録ボタンは橙の地に濃い文字、修正ボタンは青の地に白い文字で、ホバー・キーボードでのフォーカスのときに色が濃くなり影がつく |
| AC-23 | SP（414px）では、カードが画面幅に収まり、入力欄とボタンが全幅で、プレビューが画像の枠の下に出る。横スクロールは出ない |
| AC-24 | アップロードした画像は image/product/uploads/ に webp で保存される。長辺が1200pxを超える画像は縦横比を保って長辺1200pxに縮小され、1200px以下の画像は拡大されない。png の透明は保たれ、jpeg の EXIF の向きは補正される |
| AC-25 | 縦横が 8000×8000（64,000,000画素）を超える画像は「画像の縦横が大きすぎます。小さい画像を選んでください」、形式は正しいが中身が壊れた画像は「画像を読み込めませんでした。別の画像を選んでください」と表示され、登録・修正されない（画像のファイルも保存されない） |
| AC-26 | 商品金額・予約可能数に全角数字や前後の空白を入れても、半角の数として受け付け、検証も半角と同じ基準で行う |
| AC-27 | 公開側トップのおすすめ商品は、おすすめ「はい」の商品からランダムに最大3件が表示される |
| AC-28 | 修正で画像を差し替えると、保存が成功したあとに古い画像のファイルが消える（image/product/uploads/ の中のものだけ。シードの画像は消えない）。画像を選ばなかったとき・入力の誤り・重複・予約済み数未満・商品が見つからないときは、ファイルは消えも増えもしない。jpeg の EXIF の向き（1〜8）はすべて正しく補正される |
