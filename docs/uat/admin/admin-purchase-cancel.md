# UAT：管理画面の注文・予約の取消

| 項目 | 内容 |
|---|---|
| 対象ルート | POST /admin/purchase/cancel（admin.purchase.cancel）、POST /admin/reservations/cancel（admin.reservations.cancel）。ほかに注文一覧・予約一覧・会員の物理削除・マイページ・予約の受付に影響する |
| ブランチ | feat/admin-purchase-cancel |
| 根拠 | docs/uat/admin/admin-user.md のユーザー決定（未入金のまま退会した会員を物理削除できない問題の解決）、ユーザーとの相談（2026-11-06）。設計書・Figmaにない追加機能 |
| 実施日 | 2026-11-06 |

ユーザーと決めた事項：

- 対象は注文と予約の両方。未発送なら支払方法を問わず取り消せる。発送済みは取り消せない。
- クレジットカード・入金済みの銀行振込の返金は、この機能に含めない。農園が Stripe の管理画面で行い、サイトは案内だけを出す。
- 銀行振込の未入金は、Stripe の支払い（PaymentIntent）も取り消す。Stripe の呼び出しに失敗したら、取消を止めて案内を出す。
- マイページの履歴には残し「取消済」を表示する。振込先は出さない。
- 取消は管理者だけが行う。マイページからの取消は作らない（銀行振込の未入金だけの取消も作らない）。
- お客様には、取り消したいときはお問い合わせフォームから連絡するよう案内する。

この案で提案する事項（Figmaがないため、既存の部品に合わせる）：

- 取消は元に戻せない（Stripe の取消が戻せないため）。
- 「取り消す」は詳細モーダルの中に置き、会員の物理削除と同じ形の確認モーダルを出す。確認の閉じるボタンは「キャンセル」ではなく「戻る」にする（「取り消す」と「キャンセル」が並ぶと意味を取り違えやすいため）。
- 一覧には取消済みも残し、発送済のチェックの場所に「取消済」と出す。発送状況の選択欄に「取消済」を足す。
- エクスポートは取消済みを含めない。発送作業での誤発送を防ぐため。発送状況で「取消済」を選んだときだけ、取消済みを出力する。Excelの列は増やさない。
- 取消した予約の数量は、予約可能数の残りに戻す。
- 取消のメールは送らない。お客様への連絡が必要なときは農園が行う。
- 取消の案内文は、マイページの詳細モーダル・購入と予約のサンクスメール・特定商取引法の表記の3か所に載せる。お客様の画面に管理番号が出ていないため、注文日・予約日と名前を書いてもらう。
